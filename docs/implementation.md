## PRD 구체화 및 차이

- DB는 원본 JSON 문서와 조회용 정형 컬럼을 함께 저장합니다. 기록 시각 컬럼은 PostgreSQL TIMESTAMPTZ이고 JSON 시각도 UTC로 정규화합니다. PK는 `(tenant_id, id)`이며 근태에 `(tenant_id, employee_id, work_date)` 유일성 제약을 둡니다.
- 출근 구간 초과 사유 `outside_schedule`, 보호 기록 결과 `protected`, 재판정 검토 목록 `review_required`를 추가했습니다. 규칙 변경으로 기존 출근이 더 이상 유효하지 않으면 재판정 결과를 비우고 검토 사유를 남깁니다. 원본 스캔의 최초 결과는 유지합니다.
- 모드 소비 시각과 서버 스캔 시각은 잠금 획득 후 결정합니다. 일반 스캔은 가장 이른 출근과 가장 늦은 퇴근을 유지하고 관리자 보호 기록은 자동 덮어쓰지 않습니다.
- 토큰 원문을 DB에 저장하지 않습니다. 직원/고정 근무지 QR은 발급·재발급 시에만 토큰을 반환하고, `POST /qr/render`로 SVG를 만듭니다. PRD의 저장된 QR 재조회 GET은 제공하지 않습니다. 분실 시 재발급해야 하며 PNG는 미지원입니다.
- 규칙 PATCH는 전체 규칙 본문과 새 적용일을 받아 새 버전을 생성합니다. 근무지 PATCH도 현재 전체 본문을 받습니다.
- 규칙 배정 해제는 `rule_id: null`과 적용 시작일을 받습니다. 그 전 기간은 보존합니다. 기간 겹침은 409이며 기존 배정을 먼저 닫고 새 배정을 등록합니다.
- 휴대폰 토큰 유효 기간은 90일, 등록 초대와 태블릿 등록 코드는 24시간입니다. 갱신은 이전 토큰을 즉시 무효화합니다. 동의 문구/위치 보관 기간 변경 시 동의 버전도 변경해야 합니다.
- 모바일 설정과 근무지·예상 판정 조회 API를 추가했습니다. 예상 판정은 참고용이며 실제 제출 순간 서버에서 시간과 위치를 다시 검증합니다.
- `AttendanceConfig(rules=Rules(...))` 형태를 사용합니다. DB에 규칙이 하나라도 있는데 적용 규칙이 없으면 기본값으로 조용히 처리하지 않고 409를 반환합니다.
- 테스트 초기값은 출근 인정 08:00부터, 마지막 구간 이후 승인 대기, 출근 없는 퇴근 경계 18:00입니다. 모두 운영 DB 규칙에서 조정할 수 있습니다.

## 호스트에서 연결할 부분

- 실제 로그인·관리자 권한, 인증에 기반한 회사 ID 해석, 운영 관리자 UI
- 휴대폰용 HTTPS 도메인, 회사별 위치정보 동의 문구와 운영 정책
- 매일 한 번 파기 작업 실행, DB 백업/복구·비밀 관리, 알림 큐·발송 채널
- 실제 USB-COM 포트, pyserial, FastAPI lifespan 연결, Mac Mini launchd와 전원 설정
- 사내 PyPI/npm 레지스트리 이름과 배포 인증

레지스트리 게시, 운영 배포, 실제 직원 초대·알림 발송은 실행하지 않았습니다. 브라우저 검증은 테스트 DB와 테스트 직원만 사용합니다.

## 제한

테넌트 내 요청 직렬화와 일부 전체 목록 조회를 사용하는 초기 버전입니다. 대규모 데이터에서는 SQL 필터·페이지네이션과 잠금 범위를 개선해야 합니다. 자정을 넘는 교대 근무·요일/공휴일 자동 규칙·휴가 잔여일 차감은 범위 밖입니다. 특정 날짜 예외는 지원합니다.

## 0.2.0 공통 정책 및 스캐너 (2026-10-01)

- 예정 퇴근 전 재스캔은 `already_in`으로 원장을 변경하지 않습니다. 활성 직원별 일회성 지정만 `early_out`을 허용합니다. 중복 시간 판정은 유지하고 중복 시도도 별도 스캔으로 기록합니다.
- 60초 서버 서명 직원 QR을 기본값으로 적용했습니다. tenant 결합·만료·위조 검증과 QR SHA-256 소비 키를 같은 저장 트랜잭션에 포함합니다. 재사용은 409이고 실패한 저장은 소비도 롤백합니다. 원문은 영속 저장하지 않습니다.
- `att_0002`가 `att_qr_uses`, `att_scan_resolutions`를 추가합니다. 기존 `schema_v1`과 `att_0001`은 변경하지 않았습니다. 승인/무시 상태는 원본 스캔을 덮어쓰지 않는 별도 원장입니다. 명시적 보관 정책에 따른 파기·GPS 가림은 예외입니다.
- Web Serial 포트 선택·baud 선택·CR/LF 분할·150ms idle flush·수신 byte/시각·KBW 비상 입력을 패키지 컴포넌트로 옮겼습니다. 대기열 10건, 초과 프레임 전체 폐기, 취소/분리 시 정리, 네트워크/5xx/잘못된 결과에 대한 자동 재전송 방지를 검증했습니다.
- `/scanner/session`에 capability 계약과 회전 모드를 포함하고 OpenAPI에서 TypeScript 타입을 생성합니다.
- `issue_employee_qr`, `get_employee_status`, 선택적 `create_employee_router`를 제공합니다. 로그인→직원 ID 매핑은 호스트 책임입니다. 클라이언트의 `employee.getQr/getStatus`, `hasQrScanResult`로 발급 이후 결과 확인을 지원하며 QR 숨김·갱신·폴링 화면은 호스트가 연결합니다.
- 관리자 원장 조회에 스캔 ID/시각/출처/판정/처리 상태·사유와 OFFICE/EXTERNAL/MIXED/MANUAL을 추가했습니다. 원장에 수락된 출처만 근무 유형에 반영합니다.
- MaruLog 계정·팀·세션·CSRF·ADMIN·메뉴·휴가/외부근무 신청·신청번호·배포 설정은 공통 모델에 포함하지 않았습니다. MaruLog 저장소는 읽기만 했습니다.

검증: SQLite 51개, PostgreSQL 17 51개, Chrome 14개, JS 클라이언트/프레임 파서 2개 통과. Ruff, TypeScript 및 예제 빌드, OpenAPI 생성 타입 검사를 수행했습니다. 실제 USB-COM 장비는 연결하지 않았으며 Web Serial은 모의 장치로 검증했습니다.

배포는 `dist/attendance-0.2.0-bundle.tar.gz`입니다. 신규 설치/0.1.x 업그레이드와 MaruLog aqr1→aqr2 전환은 `docs/install.md`를 따릅니다. 운영 배포와 레지스트리 게시를 수행하지 않습니다.
